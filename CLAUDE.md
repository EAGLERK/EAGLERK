# MyMoney: notes for Claude Code

Personal-finance app: Vite + React + TypeScript, local-first, optional Supabase accounts. See README.md for setup.

## Skills in `.claude/skills/`

Copied from https://github.com/anthropics/skills (commit `ca45fc4`, Apache-2.0, licences included). To update, re-copy the folders from that repo.

- `frontend-design`: general design guidance. In this repo it does **not** override the existing design system. Keep the tokens in `src/styles.css`, the 44px tap targets, one primary button per screen, in-page dialogs and toasts with Undo. Use the skill for new screens and for critiquing, not to restyle what already works.
- `webapp-testing`: written for Python Playwright, which is **not installed here**. This repo's tests use Node Playwright (`npm run e2e`, `e2e:ui`, `e2e:auth`). Write new checks in `e2e/*.cjs` the same way. `scripts/with_server.py` is only useful as a server launcher around those scripts.

- `design-taste-frontend` (taste-skill, MIT, from https://github.com/Leonxlnx/taste-skill at `12af471`, installed with `npx skills add`; pinned in `skills-lock.json`): art direction for landing pages and app screens. It is built to give every project a *new* look, which would fight the design system above. For MyMoney use it for review and for new screens only, through its `references/app-screens.md` run, and keep the existing tokens, palette and type. Do not let it redraw the app's look. It writes scratch files to `.taste-skill/` (git-ignored). Its inspector needs Node 22+ and Chrome/Chromium; its image fetcher (`assets.mjs`) needs network access to public image APIs, which this cloud environment may block.
- `hallmark` (https://github.com/nutlope/hallmark at `4f6a46c`, MIT, pinned in `skills-lock.json`): for **new websites and pages only**, such as a landing page for the app. Never use it on the existing app screens unless the user types `/hallmark redesign <path>`. Its image generation is off unless `TOGETHER_API_KEY` is set, and `scripts/install-hook.mjs` (edits `.claude/settings.json`) has not been run.
- `ui-ux-pro-max` (https://uupm.cc, repo https://github.com/nextlevelbuilder/ui-ux-pro-max-skill at `9a3f14f`, MIT): a searchable local database of styles, palettes, fonts, UX rules and chart types, queried with `python3 -B .claude/skills/ui-ux-pro-max/scripts/search.py "<query>" --domain <ux|style|chart|typography|color>`. Its scripts read local CSV files only. The other six skills in the upstream repo (design, brand, slides, banner-design, design-system, ui-styling) were not copied; the upstream tests folder was left out. Use it as a **checklist source** (accessibility, touch, chart choice). Its `--design-system` generator is generic: for MyMoney it proposed glassmorphism on a dark background and a landing-page layout, which this app should not adopt. Treat its output as suggestions; the design system above wins.
- `hue` (https://hueapp.io, repo https://github.com/dominikmartn/hue at `a910e31`, MIT; the README links to hueapp.io): a meta-skill. It does not style anything itself; it studies a URL or screenshot and writes a **new design-language skill**. Say "use hue" or `/hue`. Copied without its `docs/` folder. Its `scripts/validate.mjs` runs `npx --yes js-yaml`, which downloads a package, so run it only when you accept that. URL analysis is more accurate with Chrome DevTools MCP; with WebFetch only, the skill itself warns that radii and accent colours may be off.
- `shadcn` (https://github.com/shadcn/ui, skill at `b8d7baa`, installed with `npx skills add shadcn/ui --skill shadcn`, pinned in `skills-lock.json`): **the skill itself does not apply to MyMoney's code.** The *look* of the app follows shadcn/ui's values (see `.interface-design/system.md`), copied into plain CSS from shadcn's registry source; there is no Tailwind, Radix or shadcn component in the project. It is for projects that use shadcn/ui, which needs Tailwind and a `components.json`; MyMoney uses plain CSS in `src/styles.css` and has neither. Do not run `npx shadcn@latest init` or add shadcn components here without the user asking for a move to Tailwind. When the skill loads it runs `npx shadcn@latest info --json`, and its `allowed-tools` pre-approves `npx shadcn@latest *`, which fetches an unpinned package. The skill `migrate-radix-to-base` from the same repo was not installed (MyMoney has no Radix).
- `interface-design` (https://interface-design.dev, repo https://github.com/Dammyjay93/interface-design at `2f9be32`, MIT; its README links to the site): craft rules for **dashboards and app screens**, explicitly not landing pages. This is the best fit for MyMoney. It reads and writes `.interface-design/system.md`, which is **seeded with MyMoney's real tokens and rules**, so its consistency checks hold new work to the existing design. Commands: `/design-review` (strict review, judges only, rebuilds only if asked) and `/design-deslop` (diff-scoped cleanup). Upstream's website, git hook and plugin manifests were not copied. No scripts, no network.
- When the design skills disagree, prefer `.interface-design/system.md`, then `interface-design`.
- `frontend-design`, `design-taste-frontend`, `hallmark` and `ui-ux-pro-max` overlap. If both load for one task, follow the design system first, then use one of them, not both.

## Motion

All animation uses GSAP through `src/motion/index.ts`. Do not add CSS transitions, animations or keyframes, and do not call `requestAnimationFrame` for visuals; use `gsap.ticker`. Respect reduced motion by going through the helpers in that file. Details and timings are in `.interface-design/system.md`. GSAP's licence is free for this use ("no charge" standard licence, https://gsap.com/standard-license), but read it before shipping a product whose main purpose is a visual animation builder.

## Supabase from a cloud session

Supabase project hosts (`*.supabase.co`) are reachable from the cloud sandbox, but only through its proxy, and Node's `fetch` ignores the proxy by default, so a plain `npm run check:supabase` fails with a misleading `ENOTFOUND`. Run it as:

`NODE_USE_ENV_PROXY=1 NODE_EXTRA_CA_CERTS=/root/.ccr/ca-bundle.crt npm run check:supabase`

On a normal machine, no prefix is needed. `.env.local` (git-ignored) holds the project URL and the public anon key. Never put a `service_role` key anywhere in the repo or chat.

## Building the preview page

`npm run build:single` reads `.env.local` like any build, which would bake the Supabase project and a sign-in screen into the preview page (the preview viewer has no network). Build it with the values blanked: `VITE_SUPABASE_URL= VITE_SUPABASE_ANON_KEY= npm run build:single`. For a Netlify or other real deploy, set the real values in the host's environment variables instead.

## Checks before pushing

`npx tsc --noEmit -p .`, `npx vitest run`, and the e2e suites against a running dev server. `.env.local` turns sign-in on, and the flow and UI suites test the app without it, so start their dev server with the Supabase values blanked: `VITE_SUPABASE_URL= VITE_SUPABASE_ANON_KEY= npx vite --port 5173 --strictPort`. `npm run e2e:welcome` (popup, tour, bell, browser alerts) `npm run e2e:edit` (editing, drafts, Save bar, leave guard) and `npm run e2e:notes` (Notes tab) and `npm run e2e:voice` (voice assistant, with speech stubbed) use the same blanked server as the flow and UI suites. Imported, typed-in and edited transactions are drafts, so a test that adds or imports must press `Save changes` before expecting them in the stored data, the Dashboard or the alerts. `npm run e2e:auth` starts its own servers and sets its own flags. A new test that starts from the welcome popup must skip the tour afterwards (`Skip tour`), or its popover can sit over the controls being clicked. Investing is hidden by default; run the suites a second time with `VITE_FEATURE_INVESTING=1` on the server and `INVESTING=1` on the test command.
